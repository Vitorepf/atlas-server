# Atlas AI - Tese Central do Multiplicador / Canal Soberano

Status: constitutional Layer -1. The concept is immutable; wording and examples
can evolve.

## One Sentence

Atlas is the sovereign channel through which Claude, ChatGPT, Gemini, Codex,
local models and future providers are orchestrated, governed, audited and
multiplied by Vitor's personal ecosystem.

Atlas does not compete with providers at model level. Atlas replaces direct use
of providers as the operational channel.

## Formula

```txt
Output_Atlas = Output_Provider x Multiplicador_Ecossistema
```

Provider improvement increases `Output_Provider`. Atlas improvement increases
the multiplier. The correct architecture benefits from both.

## Two Inseparable Conditions

1. **Multiplier**: memory, constitution, domain skills, routing, gates, evidence,
   Curator and local context amplify raw provider intelligence.
2. **Canal unico**: usage must pass through Atlas so Evidence, Curator, memory
   and Atlas-Vitor can learn from it.

Without multiplier, Atlas becomes a wrapper. Without canal unico, Atlas starves
because direct provider use does not create Atlas evidence.

## Feature Filter

Every feature must pass:

1. Does it multiply provider output or compete with providers?
2. Does it make Atlas the natural channel or create escape friction?

Build features that multiply and increase gravity. Reject or redesign features
that merely compete, duplicate provider apps or bypass evidence.

## Provider Antifragility

Every major provider release should make Atlas stronger:

- new model: add driver/model profile and benchmark;
- new vertical agent: extract skill/harness/policy lessons;
- new realtime/multimodal capability: expose through Surface Adapter;
- new memory/connectors: ingest as secondary source, not canonical truth;
- new tool use: govern through Runtime/Tools/Evidence.

If a provider release obsoletes an Atlas component, turn that component into an
adapter, benchmark or remove it.

## Structural Moat

Providers cannot naturally own:

- Vitor's canonical sovereign memory;
- neutral multi-provider routing;
- continuity across providers;
- immutable user constitution;
- deterministic audit/replay;
- decade-long personal Evidence Ledger;
- local personal models as pre/post-processors;
- business, cognitive and life context only Atlas sees across surfaces.

## Rivals

Rivals is the empirical immune system. It compares Atlas path vs direct provider
path on the same task, provider/model and workspace.

| Result | Meaning | Action |
|---|---|---|
| Atlas > direct | Multiplier positive | Continue |
| Atlas approx direct | Overhead without enough leverage | Investigate |
| Atlas < direct | Multiplier negative | Stop-the-line |

Negative multiplier pauses new feature work until the degrading component is
fixed, removed or demoted.

## Hard Blocks

- Training a local model as a Claude/GPT replacement.
- Locking Atlas to one provider.
- Letting surfaces call providers directly outside Kernel policy.
- Letting provider memory become canonical truth.
- Building domain/product UIs that bypass Evidence Ledger.
- Accepting direct provider use as normal for tasks Atlas should own.
