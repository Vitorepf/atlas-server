# AAEOS L7-L10 Governed Ladder Backlog

## Resumo

Fila automatica dedicada para o loop implementar a escada governada AAEOS de L7 ate L10. Ela existe porque o backlog amplo tambem contem S1-S82 legados/broad; colocar o doc amplo direto no runner automatico reabre provider burn ruim e partial decompose. Aqui ficam somente S83-S165, ja em formato que o `BuildPlanDocumentParser` e o decomposer conseguem materializar.

Contagem desta fila: 83 rows automaticas dedicadas: L7=18, L8=25, L9=20, L10=20.

## Papel no Atlas

Esta fila transforma os mapas L7, L8, L9 e L10 em trabalho real do Stewardship Loop. Ela nao promove nivel, nao prova runtime e nao autoriza efeitos soberanos sozinha; ela da ao loop candidatos concretos com classe, teste, aceite e guarda para executar via owner-flow.

## Contratos

- Cada row deve ter arquivo alvo, teste focado, status=ready e aceite testavel.
- Rows sensiveis devem produzir codigo fail-closed/read-only ate existir assinatura, receipt ou gate soberano.
- L8 so entra depois de S100/L7 real; L9 depois de S125/L8; L10 depois de S145/L9.
- L10 aqui e guard/spec/certification read-only; nao e runtime generativo.

## Fluxo

AP-790 descobre este doc pelo indice, decompõe as rows, seleciona slices com dependencias satisfeitas, executa em worktree/branch governado, valida, julga, repara se necessario e so conta merge quando main avanca.

## Regras para IA

- Nao executar promocao real, self-construction apply ou mudanca soberana sem receipt/signatures.
- Nao vender classe+teste como L7/L8/L9/L10 entregue; so receipt runtime e certificacao contam.
- Nao rebaixar guards para deixar o provider passar.
- Nao substituir esta fila por prompt amplo.

## Escopo de Implementacao

Somente os slices S83-S165 extraidos do backlog canônico. O objetivo e tornar automatico o consumo do ladder, nao duplicar autoria estrategica.
