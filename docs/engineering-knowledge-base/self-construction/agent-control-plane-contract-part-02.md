# Agent Control Plane Contract · Parte 2

## Resumo

Este recorte preserva uma parte focada do Agent Control Plane: Agent Control Plane Runtime Pilot Simulator v1 ate Schema.

## Papel no Atlas

Ajuda Self-Construction OS a coordenar sessões, filas, locks, liveness e dispatch futuro sem estado invisível.

## Onde Se Encaixa

É filho canônico de `docs/engineering-knowledge-base/self-construction/agent-control-plane-contract.md`.

## Contratos

Enquanto gates assinados não existem, runtime execution, dispatch, provider call, token spend e self-programming ficam falsos.

## Fluxo

Contrato pai → recorte de capacidade → serviço/projeção/readiness correspondente.

## Regras para IA

Não promover projeção read-only para runtime real. Não declarar conclusão sem evidência e gates.

### Agent Control Plane Runtime Pilot Simulator v1

The runtime pilot simulator layer sits on top of the certification observatory and proves the Agent Control Plane can *prepare* safe work for one or more agents without ever executing anything real. None of its ten services start processes, call Codex CLI/app, spawn subprocesses, invoke adapters, dispatch work, spend tokens, advance the next required slice, enable self-programming, write the ledger or promote completion claim. Each service is fully dry-run / read-only and is delivered behind the same `contract / preflight / implementation_packet / status` quartet pattern as the rest of the observatory; the status batch runner also iterates the ten new status projections in the same batch so coverage of the simulator layer is observed alongside the certification observatory.

### Agent Control Plane Persistent Task Queue + Claim/Lease Runtime v1

The persistent task queue + claim/lease runtime layer is the first piece of the Agent Control Plane that *persists* state to disk while still preserving every runtime-safety invariant. It promotes the simulator output of Runtime Pilot Simulator v1 into a durable local queue, with claims, leases, TTL, conflict detection, owner-only renew/release and local receipts — but never starts a provider, dispatches work, invokes an adapter, spends a token or enables self-programming. All persistence is confined to two storage prefixes:

- `storage/app/atlas/self-construction/agent-control-plane/task-queue/` — task packet records + registry
- `storage/app/atlas/self-construction/agent-control-plane/leases/` — claim/lease records + registry

Five services compose this layer; each is delivered behind the canonical `contract / preflight / implementation_packet / status` quartet and exposed through the readiness service. The status batch runner picks up all five new status projections so the certification observatory observes them alongside the existing certification stack. The chain integrity audit picks up 25 new capabilities (5 per block) and the canonical pointer remains `activate_signed_one_shot_scheduler_tick_codex_real_invoker_post_start_receipt_contract` — this layer does not advance the slice.

It also runs an invalid-scope bootstrap probe to prove empty worker scopes are blocked before handoff and the claimed lease/queue record are released. The certification proves ten per-cycle invariants (claimable supply met target, N distinct task packets, N distinct lease ids, zero write_set collisions, every dry-run lease closed, every dry-run completion verified queue `claimed` + matching queue lease/agent metadata before release, completed packets are not reclaimable, continuation summary present, evidence receipts >= 4×N, structured completion evidence valid with one validation hash per completed task, recovery resolved both expired and orphaned leases) plus cross-cycle/bootstrap invariants (`second_cycle_replenished_queue`, `recovery_never_reopens_completed`, `no_legacy_reservation_used`, `runtime_safety_all_false`, `dry_run_only_enforced`, `complete_dry_run_requires_queue_claim_binding`, `terminal_worker_bootstrap_ready`, `terminal_worker_bootstrap_returns_one_shot_packets`, `terminal_worker_bootstrap_completion_command_uses_dry_run`, `terminal_worker_bootstrap_completion_evidence_template_present`, `terminal_worker_bootstrap_operator_commands_present`, `terminal_worker_bootstrap_structured_completion_evidence_valid`, `terminal_worker_bootstrap_resumption_contract_present`, `terminal_worker_bootstrap_parallel_lanes_distinct`, `terminal_worker_bootstrap_leases_closed_by_dry_run`, `terminal_worker_bootstrap_rejects_invalid_worker_scope`) and runtime-flag invariants (queue and lease `runtime_execution_allowed/dispatch_allowed/provider_call_allowed/token_spend_allowed/self_programming_allowed/ledger_write_allowed/completion_real_allowed` all `false`). It also promotes the Terminal Loop Health Digest's cycle supervisor into the canonical invariant matrix through `terminal_loop_cycle_supervisor_present`, `terminal_loop_cycle_supervisor_launch_path_verified` and `terminal_loop_cycle_supervisor_evidence_review_path_verified`, proving the digest can choose exactly one lane-bound next command for worker launch or evidence review while keeping execute/claim/complete/provider/token flags false. Recovery is exercised by synthesising both an orphaned registry entry (no lease file) and an active-but-expired lease, then proving `expireLeases()` reconciles both without touching any `completed_dry_run` queue record. The certification surfaces `certification_hash` (deterministic, excluding ids/timestamps and run-id-scoped volatile fields), `invariants_all_true`, per-cycle `cycle_evidence`, `terminal_worker_bootstrap_probe`, `distinct_task_total`, `distinct_lease_total`, `completed_total`, `continuation_summary_count`, `evidence_receipt_count`, `queue_summary`, `lease_summary`, `runtime_safety`, `legacy_reservation_used=false` and the canonical non-execution guarantee `multi_agent_loop_certification_does_not_use_legacy_reservation_ledger`. CLI: `--agent-control-plane-multi-agent-loop-certification-{contract,preflight,implementation-packet,status}`; the status arm accepts `--agent-count`, `--cycles`, `--target-min-claimable-tasks` and `--simulate-overlap`. The service never starts processes, calls Codex CLI/app, spawns subprocesses, invokes adapters, dispatches work, spends tokens, advances the next required slice, enables self-programming, writes the evidence ledger or consults the legacy reservation ledger.

When the canonical binding already exists at `storage/app/private/atlas/self-construction/operator-submissions/terminal-loop-operational-proof-binding.json`, the finalization gate uses that canonical `@storage/app/private/...` reference in `terminal_loop_operational_proof_json_reference`, the audit-with-binding command, the final verification sequence and the finalization handoff command, while still treating the file only as read-only evidence. Both surfaces set `completion_audit_green_requires_current_snapshot_after_terminal_loop_proof=true` so the path to `Atlas Self-Programming OS` cannot skip the post-proof snapshot refresh. It now also emits `completion_finalization_operator_handoff` (`atlas.self_construction.completion_finalization_operator_handoff.v1`), a deterministic read-only handoff that classifies the current required operator artifact, mirrors blocker classification and failed checks into both the nested handoff and compact status (`completion_claim_allowed`, `next_stage_allowed`, `failed_criteria`, `failed_count`, `current_required_operator_artifact`, human/real-provider/technical blocker buckets and next-stage blocker ids), provides the exact readiness command, `--agent-control-plane-terminal-loop-operational-proof-status`, the binding persist command, replay snapshot capture, completion audit with proof binding, finalization command, ordered next-command count, final verification sequence count, and states the final success predicate while keeping `can_execute_from_handoff=false`, `can_persist_from_handoff=false`, `can_sign_from_handoff=false`, `can_call_provider_from_handoff=false`, `can_dispatch_from_handoff=false` and `can_promote_completion_from_handoff=false`. ```text
schema_version: atlas.self_construction_agent_control_plane.v1
status: agent_control_plane_ready
mode: read_only_agent_control_plane_projection
execution_allowed: false
dispatch_allowed: false
ledger_write_allowed: false

Required top-level objects: `control_plane`, `control_plane_hash`, `non_execution_guarantees`, `human_summary`.
