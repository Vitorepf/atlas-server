# Atlas AI Canonical Architecture Index

This is the compact authority root for Atlas AI architecture. If a session is
confused about which document wins, start here.

## Canonical Hierarchy

```text
Layer -1  Thesis / Multiplicador / Canal Unico / Antifragilidade
Layer 0   Constitution, identity, glossary, AtlasVault human knowledge
Layer 0.5 Documentation Operating System and session bootstrap
Layer 1   Kernel contracts: envelope, receipt, ledger, SDKs, tests, SLOs
Layer 1.5 Runtime boundaries: Laravel, Python, Go, Swift
Layer 2   Master Architecture: product, planes, domains, roadmap
Layer 2.5 Qualitative levels: P1-P7, co-strategist, Rivals Strategy
Layer 3   Operating topology: pipeline, core-vs-domain, operating system
Layer 4   Domain specs and focused domain playbooks
```

Layer -1 wins every conflict. Kernel wins executable contract conflicts. Master
Architecture wins product/domain direction conflicts unless it violates Layer -1
or Kernel.

## Conflict Resolution

When two documents conflict:

1. If it is constitutional or provider strategy, audit against Layer -1.
2. If it is executable behavior, Kernel wins.
3. If it is product/domain direction, Master Architecture wins.
4. If it is surface behavior, Pipeline/Core/Operating System must conform to
   Kernel and Master.
5. If it is legacy material, Resolver Corpus Audit or Legacy Cleanup decides
   whether to promote, reference or archive.

## Implementation Rule

New docs do not become authority by being long or persuasive. They become
authority only when linked by this index or by the relevant owner README/doc and
validated by Documentation OS.
