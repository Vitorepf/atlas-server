# Graphify Capability Taxonomy

## Purpose

Graphify is not one feature. It is a bundle of capabilities.

Atlas must classify each capability before harvesting it.

## Capability Classes

| Class | Upstream Examples | Atlas Decision |
| --- | --- | --- |
| graph generation | `extract`, `/graphify`, `update`, `cluster-only` | Harvest as AP-684 scan/report services. |
| graph query | `query`, `path`, `explain`, MCP tools | Harvest as read-only Code Intelligence tools. |
| graph analysis | god nodes, surprises, questions, diff | Harvest as Curator/Architecture Operations signals. |
| graph export | HTML, JSON, Obsidian, Wiki, SVG, GraphML, Neo4j | Optional artifacts, never authority by default. |
| cache/incremental | SHA cache, AST cache, semantic cache, manifest | Harvest into deterministic fingerprints. |
| provider extraction | Claude, Gemini, Kimi, OpenAI, Ollama, Bedrock | Rebuild behind Atlas Decide only. |
| agent install | Claude, Codex, Cursor, Gemini, VS Code, etc. | Do not use in Atlas production by default. |
| hooks/watchers | post-commit, post-checkout, watch | Future only, explicit and Ledger-visible. |
| ingest | URL/arxiv/tweet/binary-like fetch | Future only, source allowlist required. |
| global graph | global add/remove/list/path | Reject as Atlas memory replacement. |
| benchmark | token reduction benchmark | Harvest into AP-99 evaluation. |
| query memory | `save-result` feedback loop | Reinterpret as reviewed learning proposal only. |

## Safe First Harvest

The safe P1/P2 harvest is:

- schema validator.
- deterministic code/docs graph snapshot.
- source refs.
- confidence labels.
- graph query over local candidate.
- report comparing Atlas Code Intelligence and candidate graph.

This path avoids provider calls, hooks, watchers, global memory, and private
notes.

## Dangerous Capability Classes

### Agent Installers

Graphify writes instructions or hooks into assistant-specific files such as
agent docs/configs.

Atlas stance:

- useful as design inspiration.
- forbidden as automatic production behavior.
- any assistant instruction must be generated by Atlas docs governance.

### Hooks And Watchers

Hooks/watchers can create invisible state updates.

Atlas stance:

- no default hook.
- no background watcher without explicit AP.
- any future watcher must record schedule, source scope, output path, and
  evidence event.

### Provider Extraction

Graphify can send docs/PDF/images to a model.

Atlas stance:

- provider extraction is powerful.
- direct calls are forbidden.
- Atlas provider driver, Decision Receipt, budget, and privacy gates are
  mandatory.

### Global Graph

Graphify can merge project graphs into a global graph.

Atlas stance:

- reject as memory core.
- graph merge is artifact-level only.
- Atlas memory requires triage, contradiction, decay, privacy, and review.

## MCP Capability Mapping

Graphify MCP tools map cleanly to future Atlas tools:

| Graphify MCP Tool | Atlas Equivalent |
| --- | --- |
| `query_graph` | query bounded graph context slice |
| `get_node` | inspect entity/source ref |
| `get_neighbors` | inspect direct relationships |
| `get_community` | inspect cluster hint |
| `god_nodes` | architecture centrality report |
| `graph_stats` | graph quality/readiness report |
| `shortest_path` | explain relation path |

Atlas additions required:

- auth.
- source budget.
- confidence filters.
- privacy redaction.
- receipt reference.
- no mutation.

## Command-To-Atlas Rule

Every Graphify command must be classified as one of:

- `adopt_native`.
- `adapt_native`.
- `reference_only`.
- `reject`.

No command is allowed to enter Atlas as `copy_unknown`.

## Final Rule

Graphify's capability breadth is exactly why it is valuable and dangerous.

The enterprise move is to harvest the mental model and selected mechanisms while
keeping Atlas as the only operational authority.
