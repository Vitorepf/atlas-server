# Atlas Holding To World Action Hardening Initiative

## Resumo

Este arquivo mantem o caminho antigo `atlas-autonomous-company-os-genesis-initiative.md`
por compatibilidade, mas corrige sua autoridade canonica.

Genesis **nao** e proximo OS. Genesis **nao** e AGOS. Genesis **nao** promove
AAEOS diretamente para Autonomous Company OS. O Atlas ja possui:

```text
Atlas Autonomous Intelligence OS
-> Domain Company Runtimes
-> Autonomous Holding OS
-> AAEOS como company/runtime de engenharia
```

O proximo frontier operacional nao e criar outro OS. E endurecer a Holding para
o **World Action Engine governado**: acao externa com mandato, preflight,
approval, rollback, evidence, control plane e external side effects desligados
por default.

## Papel no Atlas

Este doc e um guarda-corpo de documentacao. Ele existe para impedir que uma IA
trate uma visao de proximo patamar como permissao para criar OS, domain,
runtime ou gate paralelo.

Seu papel pratico:

- preservar a autoridade da Holding sobre empresa multi-dominio;
- preservar a autoridade de Domain Runtime sobre manifests/registry/maturity;
- preservar a autoridade de Evidence/ASRE sobre outcome real;
- preservar a autoridade de TEOS sobre contrafactual;
- apontar o hardening correto para World Action Engine governado.

## Onde Se Encaixa

```text
Atlas Autonomous Intelligence OS
-> Domain Company Runtimes
-> Autonomous Holding OS
-> AAEOS / domain companies integradas
-> Holding hardening
-> World Action Engine governado
```

Este doc fica entre a linha evolutiva macro e os owners de runtime. Ele nao e
owner de runtime.

## Owner Map Corrigido

| Capacidade util que apareceu no factory | Owner canonico real | Acao correta |
|---|---|---|
| Multi-functional substitution | `atlas-autonomous-intelligence-operating-system` + `atlas-domain-company-runtimes` + `atlas-ai-autonomous-holding-operating-system` | Nao criar OS novo; usar Holding/Domain existentes |
| Domain/departamento novo | `domains/domain-routing-governance.md` + `atlas-domain-runtime-contract.md` + `atlas-agentic-engineering-os-department-contract.md` | `atlas-domain-runtime-creation-gate.md` vira extensao estrita |
| Reality/outcome gates | `atlas-evidence-certification-runtime.md` + `atlas-strategic-reality-engine.md` + Holding scorecards | `atlas-reality-outcome-gates.md` vira taxonomia/subcontrato |
| Counterfactual futures | TEOS-I3/I4 + ASRE/RealitySandbox | Nao criar Counterfactual Reality Engine paralelo |
| Architecture self-redesign | `atlas-ai-self-construction-os.md` + Verified Evolution/Evidence/Trust | `atlas-architecture-evolution-proposal-runtime.md` fica sub-runbook |
| Federation/soberania | `atlas-sovereign-operating-system.md` + `atlas-epistemic-operating-system.md` | Futuro distante, sem doc filho aqui |
| External real-world action | Holding external action mandates + World Action Engine lineage | Proximo hardening real |

## Correção De Linha Evolutiva

Use a linha evolutiva canonica, mas nao pule owners existentes:

```text
AAEOS operacional
-> integrado a Domain Company Runtime / Holding
-> Holding supervisionada com scorecards e mandatos
-> World Action Engine governado
-> Civilization Intelligence Engine
```

Autonomous Company OS nao deve ser reintroduzido como doc/runtime novo enquanto
`atlas-ai-autonomous-holding-operating-system.md` ja governa a holding
multi-dominio.

## Contratos

- Este doc e roadmap/compatibility bridge, nao runtime.
- Nenhum service, command, model ou table deve ser criado com namespace Genesis.
- Child docs devem declarar seu owner canonico real e nunca depender deste doc
  como autoridade de runtime.
- External action continua bloqueada por default. Mesmo com Holding target 9,
  side effects externos exigem mandate, preflight, operator approval, second
  reviewer, rollback/compensation e audit trail.
- Dominio sensivel exige safety/sovereignty lock antes de qualquer claim
  operacional.

## Fluxo

```text
Proposta de proximo patamar
-> checar owner canonico existente
-> se owner existe, reparentar como subcontrato
-> se tocar external action, route para Holding/World Action readiness
-> se tocar domain novo, route para Domain Routing Governance
-> se tocar outcome, route para Evidence/ASRE/Holding
-> se tocar arquitetura, route para Self-Construction OS
-> bloquear qualquer OS/sigla/camada paralela
```


## Escopo De Implementacao

Esta iniciativa nao gera codigo diretamente. Implementacao decorrente vive nos
owners:

- Holding: mandates, scorecards, control tower, activation cockpit, external
  action preflight e manual/supervised execution.
- Evidence/ASRE: reality outcome signals e reports.
- Domain Runtime: creation gate estrito usando registry, manifest, maturity e
  routing governance existentes.
- Self-Construction: structural redesign proposal apenas como proposal, nunca
  auto-mutacao sem gates.

## Dependencias

- `atlas-autonomous-intelligence-operating-system`: OS-mae multi-dominio.
- `atlas-ai-autonomous-holding-operating-system`: governor/read model da
  holding multi-dominio.
- `atlas-domain-company-runtimes` e `atlas-domain-runtime-contract`: owners de
  domain company, manifest, registry, maturity e handoff.
- `domains/domain-routing-governance.md`: Domain Creation Gate existente.
- `atlas-ai-evolution-lineage-and-target-state`: linha evolutiva macro.
- `atlas-cartography-nomenclature-contract` e `atlas-canonical-glossary-and-naming`:
  impedem patamar decorativo e sigla paralela.

## Regras Para IA

- Nao criar AGOS, ACSL, ASRL ou Genesis OS.
- Nao declarar promocao direta AAEOS -> Autonomous Company OS com base neste doc.
- Nao criar domain/runtime/gate paralelo quando owner existente cobre o caso.
- Nao criar Counterfactual Reality Engine paralelo a TEOS.
- Sempre perguntar: "qual owner canonico ja existe?" antes de propor doc novo.
- Para proximo patamar operacional, priorizar Holding -> World Action Engine
  governado, nao naming novo.

## Evidencias

- `php artisan atlas:ai:autonomous-holding --json` prova a Holding como camada
  real de readiness.
- `php artisan atlas:ai:autonomous-holding --action=enterprise-buildout --json`
  prova company packets, cross-company fabric e portfolio governance.
- `atlas-domain-runtime-contract.md` prova Domain Runtime como owner de manifests,
  registry, maturity e handoff.
- `domains/domain-routing-governance.md` prova Domain Creation Gate existente.
- TEOS-I3/I4 docs provam counterfactual owner existente.

## Riscos

- **Critico**: IA tratar Genesis como OS novo e criar runtime paralelo.
  Mitigacao: `genesis-not-promoted-to-os` e owner map corrigido.
- **Critico**: IA declarar Autonomous Company OS futuro ignorando a Holding.
  Mitigacao: depender de `atlas-ai-autonomous-holding-operating-system`.
- **Alto**: Domain Creation Gate paralelo ao registry/maturity existente.
  Mitigacao: `atlas-domain-runtime-creation-gate.md` e extensao estrita.
- **Alto**: outcome gate virar KPI solto ou promocao paralela.
  Mitigacao: alimentar Evidence/ASRE/Holding.
- **Critico**: external action habilitada sem mandato.
  Mitigacao: Holding external action mandates e manual/supervised execution.

## Exemplos

### Exemplo 1: IA propoe AGOS

Resultado correto: bloquear nome/camada. Mapear a intencao para Holding,
Domain Runtimes e World Action readiness.

### Exemplo 2: IA propoe trading domain

Resultado correto: aplicar Domain Routing Governance primeiro; se dominio novo
for inevitavel, usar Domain Runtime Contract, safety/sovereignty lock e revisor
humano licenciado. Nenhuma ordem real e autorizada por este doc.

### Exemplo 3: IA propoe Counterfactual Reality Engine

Resultado correto: nao criar engine paralelo. Usar TEOS-I3/I4 e ASRE como
owners canonicos de contrafactual e outcome.
