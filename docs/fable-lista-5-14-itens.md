## Bloco A — Autonomia de pauta + composição (o salto qualitativo)

**L5-1 ⭐ Autonomia de pauta governada (o O-14 original).**
Hoje o loop executa backlog; o salto: o Atlas PROPÕE a própria pauta semanal — lê seus
sinais (scorecard, perdas do loss-observer, gaps do Dev beat-test, uso real do operador)
e emite uma proposta de "o que atacar esta semana" em nível SUGGEST, que o operador
aprova com 1 decisão. Nunca auto-executa pauta nova; aprovação destrava a semana.
DoD: 1ª pauta proposta+aprovada+executada de ponta a ponta.

**L5-2 ⭐ Loop→Obra bridge: mudanças COMPOSTAS (multi-arquivo).**
Hoje os merges são micro-diffs de 1 arquivo. O salto: quando um intent precisa de N
arquivos (feature, refactor), o loop escala automaticamente para uma obra Forge multi-nó
(gpt-5.5), com os mesmos gates + parked-review para mudanças grandes. O loop gradua de
"tweaks" para "features". DoD: 1 feature multi-arquivo entregue pelo bridge.

**L5-3 — Auto-cura da suíte real.**
A suíte de ~24k testes tem um lote vermelho ambiental/mid-refactor (memória conhecida).
O loop ganha um modo "test-healer": triagem honesta (ambiental vs real), fix-forward dos
reais, quarentena documentada dos ambientais. O repo converge para verde permanente.
DoD: tendência de vermelhos medida caindo semana a semana.

**L5-4 — Self-construction de ferramentas (a tese central).**
Quando o loss-observer detectar um gap RECORRENTE de capacidade (ex: falta um fixture
builder, um linter de contrato), o Atlas constrói a própria ferramenta — obra gated,
parked para revisão, nunca silencioso. DoD: 1ª ferramenta auto-construída em uso real.

## Bloco B — O Atlas aprende a se OPERAR (os diais se ajustam sozinhos)

**L5-5 ⭐ TAXA²: diais auto-ajustáveis (o O-11 original).**
Cenários/task, watermark, cooldowns, limites de drain — hoje fixos na config. O salto:
ajuste automático por outcome medido (mais cenários onde a taxa de certificação é baixa,
menos onde converge rápido), raise-only/clamped, kernel-sanctioned. DoD: dial mudou
sozinho com receipt explicando o porquê, e o número que o justificou.

**L5-6 — ADML auto-routing por custo×outcome (o O-12 original).**
Cada classe de task roteia para o provider mais BARATO que historicamente certifica
(gpt-5.5 vs M3 por tipo de alvo), usando o custo medido (L3-10) + outcomes. Fallback
sobe de tier só quando o barato falha. DoD: % de tasks roteadas a M3 com taxa de
certificação preservada; economia medida.

**L5-7 — Governador de custo diário.**
O eixo custo vira CONTROLE, não só telemetria: budget/dia (tokens+$) com throttle
automático (menos cenários, pausa) ao se aproximar do teto, e relatório custo-por-merge.
DoD: simulação de estouro → throttle automático; custo-por-merge no digest.

**L5-8 — Frota: pool paralelo ON de verdade (o O-10 original).**
O worker pool paralelo existe gated-off. Ligar com disciplina de lease provada (2→4
workers), medindo throughput vs contenção, com o keepalive cobrindo cada worker.
DoD: 4 workers estáveis por 24h; cenários/hora ≥2× o serial.

## Bloco C — Expansão de domínio (Atlas opera além de si mesmo)

**L5-9 ⭐ Campanhas multi-repo: o Atlas trabalha nos SEUS projetos.**
O loop hoje evolui o atlas-server; o operador tem blackink, nivor, etc. O salto: campanha
workspace-scoped em OUTRO repo (mesmos guards, porta governada por-repo, never-merge
default lá também). O Atlas vira a equipe de manutenção de todos os seus projetos.
DoD: 1 merge governado num repo não-Atlas, auditado.

**L5-10 — Dev fecha os gaps do beat-test.**
O L4-9 mediu onde o Dev perde para Claude Code/Cursor; cada gap vira item executado
(contexto? velocidade? qualidade de edição?). Re-rodar o beat-test até o Dev VENCER em
tarefa média — a taxonomia do operador cumprida. DoD: beat-test re-rodado com vitória
documentada (ou gap residual honesto com causa).

**L5-11 — Memória learn→recall→USE com lift medido.**
Os learning candidates do compounding ficam held_for_evidence; o resolvedor de evidência
promove os que comprovadamente AJUDARAM (recall usado em decisão que certificou). Fecha o
ciclo: merge→learning→recall→merge melhor. DoD: lift de recall medido em A/B de tasks.
